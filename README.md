# 从第一行 C++ 到读懂无人船工程

这份大纲写给学过 C、刚接触 C++ 和 ROS 2 的读者。课程围绕一个具体问题展开：香橙派怎样收到缆长、方向和深度，又怎样算出子船相对母船的位置？读到最后，目标是能自己找到对应源码，解释计算什么时候发生，判断一条异常的位置消息该从哪里查起。

工程采用 Ubuntu 22.04、ROS 2 Humble（Robot Operating System 2，机器人操作系统第二代）和 C++17。教学以中文讲解，首次遇到缩写时给出英文全称和中文含义。代码注释会说明一行代码操作了哪个对象、数据从哪里来、为什么需要这样的写法。适合与 C 对照的地方会并排展示两种写法。

## 第一阶段 · 从会写 C 到能读 C++ 的普通函数

| 课次 | 要弄懂的问题 | 从哪里入手 |
| --- | --- | --- |
| 01 | 怎样打印一行字和一个数？ | 从熟悉的 `printf("length = %.1f\n", length);` 过渡到 `std::cout << "length = " << length << '\n';`。逐个认出头文件、`main`、命名空间 `std`、输出流和换行，再看两者怎样控制小数位数。 |
| 02 | 怎样看懂一个有单位的计算式？ | 用缆长、深度和角度理解 `double`、`bool`、大括号初始化、`const`、`constexpr` 和 `std::sqrt`。对照整数除法和浮点运算，区分代码里的数值、物理单位和变量有效范围。 |
| 03 | 一次函数调用究竟改了谁？ | 从 C 用指针传回结果，过渡到 C++ 的值传递、引用和常量引用。读 `imu_orientation.hpp` 的函数签名，把输入、输出参数和表示成功与否的返回值分开。 |
| 04 | 一组系数怎么保存？没有数据怎么表示？ | 从 C 数组走到 `std::array`、范围 `for`、`auto`，用角度标定函数读一次真实循环。再看 `std::optional<double>` 怎样区分“还没收到深度”和“深度为零”。由此认识模板名后面的尖括号。 |

## 第二阶段 · 读懂一个对象从创建到销毁的过程

| 课次 | 要弄懂的问题 | 从哪里入手 |
| --- | --- | --- |
| 05 | 为什么把数据和函数放进一个类？ | 先写一个 C 风格的“滤波状态结构体 + 更新函数”，再读 `imu_test1.cpp` 的 `AngleFilter`。区分类、对象、成员变量、成员函数、`public` 和 `private`，解释两个滤波对象为什么能各记各的历史。 |
| 06 | 对象出生时，谁给它初始值？ | 读构造函数、成员初始化列表、作用域、析构和对象生命周期。用 `PoseNode` 区分“它本身是一种节点”的继承关系与“节点里面持有发布器”的组合关系。 |
| 07 | 为什么有时写点号，有时写箭头？ | 从 C 指针回到对象访问，区分对象、引用、指向对象的指针和智能指针。读 `std::make_shared` 与 `SharedPtr`，解释为什么构造函数已经返回，订阅器还要继续存在。 |
| 08 | 一段函数为什么可以留到以后再执行？ | 从 C 函数指针讲到可调用对象、匿名函数 lambda、参数列表与 `[this]` 捕获。沿 `pose_node.cpp` 看“登记回调”和“真正收到数据，执行回调”分别发生在什么时候。 |

## 第三阶段 · 在电脑上找到、编译并启动船的代码

| 课次 | 要弄懂的问题 | 从哪里入手 |
| --- | --- | --- |
| 09 | 源码、运行环境和实物设备各在哪里？ | 对照 Windows、WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）里的 Ubuntu 和香橙派。理解终端、路径、进程、环境变量，以及电脑上运行定位节点时，传感器输入可以来自哪里。 |
| 10 | 打开文件夹后先看什么？ | 从工作空间 `orangpi_ros2/` 进入 `src/usv_localization/`。前一个 `src/` 装功能包，包内的 `src/` 装 C++ 源码。`launch/` 放启动描述，`config/` 放配置，`test/` 放测试。构建后再认识 `build/`、`install/` 和 `log/`。USV 是 Unmanned Surface Vehicle，无人水面艇。 |
| 11 | 一个 `.cpp` 文件怎样变成能启动的程序？ | 从声明、定义、头文件、编译、链接、安装读到 `package.xml` 与 `CMakeLists.txt`。弄清包清单、CMake 构建说明、`ament_cmake` 和 `colcon` 分别负责什么，为什么同一个包能生成四个可执行程序，以及加载工作空间后 ROS 2 怎样找到它们。 |

## 第四阶段 · 跟一条消息走过 ROS 2

| 课次 | 要弄懂的问题 | 从哪里入手 |
| --- | --- | --- |
| 12 | 包、程序、进程、节点、话题和消息各指什么？ | 用 `pose_node` 和 `/sensor/cable_length` 画通信关系。区别话题名与消息类型，读 `std_msgs/msg/Float64` 的 `data` 字段。顺带认识连续数据用的话题、一次请求和响应的服务，以及带反馈的长任务动作。 |
| 13 | 怎样写一个订阅器和一个发布器？ | 在 `pose_node.cpp` 逐行拆开 `create_subscription`、回调参数、消息字段、`create_publisher` 和 `publish`。同一个节点怎样订阅三个输入，又把解算结果发到另一个话题？ |
| 14 | 程序启动后，到底谁在调用我的函数？ | 沿 `main → init → 创建节点 → spin → shutdown` 读执行顺序。比较“有输入才计算”的位置节点与母船航向节点的 20 毫秒定时器，读懂执行器、回调、频率，以及缓存值和新测量的区别。 |
| 15 | 两边都启动了，为什么还收不到数据？ | 从本包的传感器订阅设置讲 QoS（Quality of Service，服务质量）。按话题名称、消息类型、发布者与订阅者发现、可靠性策略和队列深度，理解哪些问题会阻止连接，哪些会影响丢帧或延迟。 |
| 16 | 四个节点怎样一起启动？怎样切换配置？ | 读 `localization.launch.xml`。区分启动参数、节点参数、命名空间、绝对话题名和话题重映射。沿 `with_ekf` 开关找到额外启动的节点，再到 `ekf.yaml` 找算法配置。 |

## 第五阶段 · 读通船上的定位算法和数据来源

| 课次 | 要弄懂的问题 | 从哪里入手 |
| --- | --- | --- |
| 17 | 传感器给的是四元数，缆绳方向从哪里来？ | 读 `imu_orientation.hpp` 和 `imu_test1.cpp`。从 IMU（Inertial Measurement Unit，惯性测量单元）讲到姿态、四元数、偏航角、角度跨界与滤波，追到原始缆绳方位角话题。 |
| 18 | 为什么还要标定角度？母船航向能直接当缆绳角吗？ | 读 `cable_angle_calibrator.cpp` 的多项式系数，再对照 `mother_usv_msg_node.cpp` 的安装偏置。画出两条独立数据路径，标明各自的零方向、角度单位和输出话题。 |
| 19 | 船怎样用三项测量算出一个三维位置？ | 精读 `pose_node.cpp`。从勾股定理推出水平距离，再把它投影到船体坐标轴。缆长 5 米、标定后方位角 0 弧度、相对深度 3 米时，读出母船坐标下的位置 `(4, 0, −3)` 米。接着追踪三路输入首次到齐、某一路更新、深度超过缆长时的执行分支。 |
| 20 | 一个位置为什么还要带坐标系、时间和协方差？ | 从 `/solver/pose` 消息讲到 TF（transform，坐标变换）、母船与子船机体坐标系、传感器安装方向，以及协方差表达的测量不确定性。读配置理解 EKF（Extended Kalman Filter，扩展卡尔曼滤波器）如何利用相对位置和子船 IMU 得到滤波后的里程计。 |

## 第六阶段 · 从读懂程序到维护和迁移整套工程

| 课次 | 要弄懂的问题 | 从哪里入手 |
| --- | --- | --- |
| 21 | 软件里的数字怎样连到船上的设备？ | 回看 ROS 1 的 `mz_usv/src/auto_pwm.cpp` 和 `usv/src/motor.cpp`。分别跟踪手柄到母船左右推进器电调的指令，以及缆绳电机和缆长反馈。结合串口、GPIO（General-Purpose Input/Output，通用输入输出）、PWM（Pulse-Width Modulation，脉宽调制）和 Linux 设备命名规则，理解香橙派、飞控与电机控制器的分工。 |
| 22 | 从 ROS 1 移植到 ROS 2 时，哪些对应关系必须检查？ | 对照 Noetic 的 `catkin_ws` 和 Humble 的 `orangpi_ros2`，逐项看通信接口、构建依赖、启动文件、参数与设备驱动。区分已移植的定位计算、由外部提供的输入以及需要上船核实的硬件接口。 |
| 23 | 出现异常时，怎样一步步缩小范围？ | 用“没有位置输出”“位置方向相反”“停止更新深度却仍在发位置”三个现象，学习看节点、查话题连接、查频率、看消息字段与日志，再回到对应回调。认识录包回放如何帮助复现间歇故障。 |
| 24 | 怎样判断一项修改确实改善了工程？ | 读 `test/test_localization.py` 怎样提供输入、等待节点通信并检查输出。讨论两个具体改进：母船首帧前的默认航向如何区分于真实零度，某路输入过期后怎样处理。分别说明原行为、改法会影响哪些订阅者、用什么测试验证。 |

### 实船代码的阅读边界

当前 ROS 2 包含四个定位计算节点，可按需启动 EKF。推进器、缆绳电机和串口设备接入会结合原 ROS 1 工程讲解。已备份的旧工作空间中可以找到相对深度的订阅端，其实船发布来源仍待确认。课程会把能从源码证明的行为和需要硬件验证的结论分别标明。
