# 拿着数字读缆绳 IMU、滤波和标定

三个节点的方向数字容易混在一起。本篇选几组输入，沿 `imu_orientation.hpp`、`imu_test1.cpp`、`cable_angle_calibrator.cpp` 和 `mother_usv_msg_node.cpp` 得出数值。上一章已经讲了消息字段，这里重点放在运算过程、分支和各自的参考意义。

## 1. 从两组输入想象绕轴旋转

用右手坐标系，母船向前 X、向左 Y、向上 Z。传感器局部的“向下”先写成向量 `(0, 0, -1)`。为了手算，假设选用的四元数表达绕 X 正向旋转 α：

```text
q = (sin(α/2), 0, 0, cos(α/2))
绕 X 的旋转矩阵：
[ 1       0         0   ]
[ 0     cos α    -sin α ]
[ 0     sin α     cos α ]
乘局部向量 (0, 0, -1) 得 (0, sin α, -cos α)。
```

如果 α 为 0，向量仍朝正下方。若 α 为 0.5 弧度，新的 Y 是 `sin(0.5) ≈ 0.4794`，新的 Z 是 `-cos(0.5) ≈ -0.8776`。水平向量几乎纯 Y 正向，因此 `atan2(y, x)` 为 π/2。这个纯 X 旋转的 RPY 偏航为零。输入倾角是 0.5 弧度，经过倾角滤波后超过 0.035 门限，程序将大约 π/2 的相对方位送给方位滤波器。

给出这一组旋转的四元数分量是 `(sin(0.25), 0, 0, cos(0.25))`。角度的二分之一进正余弦是四元数构造的一部分。右手轴旋转对应的 Y 正向来自矩阵乘法。不能凭“绕 X 转了 0.5”直接把相对方位填为 0.5。它们量的是不同的角：

| 数值 | 量的是什么 | 这组样例 |
| --- | --- | --- |
| `roll` | 传感器绕 X 倾转的 RPY 分量 | 0.5 rad |
| `tilt` | 缆绳和向下竖直线的夹角经滤波后的值 | 逐步接近 0.5 rad |
| `atan2(y, x)` | 缆绳投影在水平面向哪个方向 | π/2 rad |
| `yaw` | 该缆绳 IMU 的 RPY 偏航 | 0 rad |
| `angle.data` | 经过程序门限和滤波的原始方位值 | 逐步接近 π/2 rad |

如果只给这组 IMU 一个绕 Z 的旋转，向下向量还是向下。可以有 yaw，仍没有足够的水平投影供缆绳方位计算。把航向角直接作为缆绳平面方向，无法从竖直状态推导出来。

## 2. 为什么回调先滤倾角，再判断门限

同一条姿态消息产生倾角和水平投影。源码先更新倾角估计，再用估计值与约 2° 的门限做判断。它希望近竖直时别把极短水平投影上的噪声放大成方向跳动。滤过的倾角接近阈值时，有一定历史影响，第一次看到一个很小或很大的测量，分支由估计值决定。要排查现场“偶尔角度是 0”，比对原始姿态、倾角估计和分支门限是有针对性的做法。

门限之下输出原始角 0，是工程的兼容行为，含义是本算法在该状态采用零方位。若下游需要区分“真实正前方”和“水平投影太短”，可以另外提供质量或可用性信息。从数值话题单看一个零，无法分辨这两种来源。和初始化航向的零是类似的接口设计问题，但来源不同。这里仍发布一个值，是算法明确选的默认分支。

## 3. 用头两帧解释 AngleFilter 在记什么

打开 `AngleFilter::update`，按“预测方差、算增益、算短角差、更新估计、更新方差”的顺序读。源码初始估计为 0，初始方差为 0.1。参数 `dt = 0.01`，`q = 0.0001`，`r = 0.005`。`dt` 是每帧使用的时间步长。这里 `q` 是过程噪声参数，`r` 是测量噪声参数。想看它们怎样影响更新，可以手算两次 0.5 弧度输入：

```text
第一帧：
  predicted_variance = 0.1 + 0.0001 × 0.01 ≈ 0.100001
  gain = 0.100001 / (0.100001 + 0.005) ≈ 0.952381
  short_error = 0.5 - 0.0 = 0.5
  estimate ≈ 0.47619
  variance ≈ (1 - 0.952381) × 0.100001 ≈ 0.004762

第二帧：
  predicted_variance ≈ 0.004763
  gain ≈ 0.004763 / (0.004763 + 0.005) ≈ 0.488
  short_error ≈ 0.5 - 0.47619 ≈ 0.02381
  estimate ≈ 0.48781
  variance 继续更新并留到下一次。
```

第一帧对旧估计权重小，快速接近测量。第二帧只做更小修正。观察时 `estimate_` 是这帧结束得到的角度，`variance_` 则影响下一帧的更新幅度。两项的生存期属于滤波对象，不是 `update` 的局部变量。若把它们误改成每次调用都重新初始化，连续帧就不会建立历史。节点用两个分开的 `AngleFilter`，意味着上述两帧推导可以分别对倾角和方位执行，互不共享状态。

模型用了固定 `dt`。例如真实驱动 100 Hz 时，平均每帧约 10 毫秒，与它对应。若板端实际只收到 10 Hz，代码每帧仍增加 `q × 0.01`，原来的“每秒累计的过程不确定度”解释就变了。要改成使用真实时间间隔，需要先记录采样或接收时刻，并明确大间隔、乱序和缺帧的规则。仅把常量改大能改变平滑程度，却不会补出缺失的测量。

### 从 +179° 到 −179° 怎么变成两度

在角度圆上，+180° 与 −180° 表示相同方向。设 `previous = 179°`，`measurement = -179°`。差为 −358°，加一圈就等于 +2°。`atan2(sin(error), cos(error))` 自动得到与差值同方向等价、落在主值区间的角差。更新时用增益乘约 +2°，就在旧估计附近小步移动。直接用 −358° 则会跨过很大角度，这违背“从上一帧跟踪旋转”的目的。

同理，从 −179° 到 +179° 的短角差约 −2°。若两角相差恰好半圈，主值一端可以随符号和数值舍入落在 +π 或 −π。实际测试应以等价方向或最短角差判断，不要只比较某一个数值区间端点。源码使用同一种规约方式避免把正常跨界解释成接近一圈的突变。

## 4. 标定节点里先减什么，再乘什么

原代码的顺序对结果有影响：

1. 原始角进入后是否有限。有效才继续。
2. 用读数减安装零偏，得到拟合用的输入变量。
3. 当变量处在源码设定阈值以下，把它加一整圈、搬到另一侧拟合区间。
4. 让多项式将拟合输入映射到标定角。
5. 最后再把输出规约回主值区间，并发布。

这里“输入区间展开”和“输出规约”不同。先移到拟合的区间，再使用拟合曲线，最后选择下游的角度表达区间。改成先输出规约或任意交换步骤，可能让同一个方向进入多项式中的另一个数值，结果就会不同。

原始角刚好 0 的时候，减零偏后得到一个小负数。用 `x` 表示这个量，多项式中的一次项和常数项主导小范围结果。结合源码系数可得到约 −0.024 弧度，所以定位 Y 会有约 −9.7 厘米的小量。它是标定造成的合理差别。需要确认坐标时，把“输入原始角”和“直接注入标定后角”明确写在记录中：

| 选择的测试入口 | 同样输入写 0 | 下游看到的方位 | 有什么结论 |
| --- | --- | --- | --- |
| 直接给标定后话题 | 0 rad | 0 rad | 只查定位几何，Y 约为 0 |
| 给原始方位话题 | 0 rad | 约 −0.024 rad | 同时查标定，Y 有小负量 |
| 给缆绳 IMU 的单位四元数 | 零旋转 | 因竖直分支，原始角 0，再标定 | 还覆盖姿态有效性、默认分支和通信 |
| 给母船 IMU 的单位四元数 | 零旋转 | 母船航向发布 180° | 另一条链，不改变上述位置订阅 |

校准多项式是基于特定安装条件得到。换一个传感器安装角或船体机械结构后，拟合系数可用于重现原船行为，实船准确度仍要测。看了系数也不能推断输入上的每次小偏差都是硬件坏了。有来源、范围和记录时才适合判断是否调整。

## 5. 母船航向为何容易在单位上读错

输入四元数也通过 `read_orientation` 校验。然后程序提取 yaw，单位弧度。原安装约定需要加 π。使用浮点取模把值限制到一整圈，再用 `180.0 / pi` 转成度。可以从几个例子判断偏置是否按预期起作用：

| 四元数表示的 yaw | 加 π 后（度数便于阅读） | 规约后的母船航向 |
| --- | --- | --- |
| 0° | 180° | 180° |
| +90° | 270° | 270° |
| −90° | 90° | 90° |
| +180° | 360° | 约 0° |
| −180° | 0° | 约 0° |

母船节点的回调更新航向缓存，定时器才发布。所以“收到 270° 后继续看到 270°”一般符合程序写法。需要确认新姿态是否持续来到，查母船 IMU 本身的采样或接收。研究滤波器时不要把定时器的 50 Hz 当成母船 IMU 的输入频率。

## 6. 一个不用 ROS 的角度观察例子

下面示例用 C++17 打印规约后的短角差，以及两个位置相邻的例子。它展示公用的数学技巧，不需要 tf2。

```cpp
#include <cmath>
#include <iomanip>
#include <iostream>

double wrap_to_pi(double radians) {
    // 在单位圆上求同一方向的主值角。
    return std::atan2(std::sin(radians), std::cos(radians));
}

int main() {
    const double pi = std::acos(-1.0);
    const double radians_per_degree = pi / 180.0;
    const double previous = 179.0 * radians_per_degree;
    const double measurement = -179.0 * radians_per_degree;

    const double direct_error = measurement - previous;
    const double short_error = wrap_to_pi(direct_error);
    const double estimate = wrap_to_pi(previous + 0.5 * short_error);

    std::cout << std::fixed << std::setprecision(2)
              << "direct error " << direct_error / radians_per_degree << " deg\n"
              << "short error " << short_error / radians_per_degree << " deg\n"
              << "next estimate " << estimate / radians_per_degree << " deg\n";
    return 0;
}
```

第一行输出约 −358°，第二行约 +2°，下一次估计靠近 180°。第三行可能显示 +180° 或 −180°，这两个表示同一个方向。示例把增益用 0.5 固定，方便观察规约本身。实船 `AngleFilter` 用预测方差和测量噪声计算增益，这块请回看第三节。
