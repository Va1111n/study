# 无人船怎样从传感器数据得到相对位置

这一篇从第 17～20 课展开。每一步都问三个问题：**输入是哪个物理量？这一步为什么需要它？结果由谁继续使用？** 先固定一个场景。母船船头定义为前方，缆绳在水平面上的投影向船头，子船在水下。我们要用以母船为参考的三元组表示子船位置。

## 17 · 从缆绳 IMU 的四元数读出方位角

### 位置和姿态是两个概念

位置回答“东西在哪里”，姿态回答“东西朝哪里”。IMU（Inertial Measurement Unit，惯性测量单元）消息可能包含角速度、线加速度和估计姿态。角速度描述旋转得多快，姿态描述当前朝向。船这里使用 `orientation` 作为旋转信息。`read_orientation` 先检查姿态是否有效，接下来才用四元数转方向。缺姿态的数据即使还有加速度，也不能沿这个算法直接替代四元数。

四元数在消息里按 `(x, y, z, w)` 排列。对旋转，单位四元数的模长为 1。若绕某单位轴转 θ，前三个分量可写为“轴向量乘 `sin(θ/2)`”，最后一个是 `cos(θ/2)`。绕 Z 轴 90° 的例子里，x 和 y 为 0，z 与 w 都是约 0.7071。`(0,0,0,1)` 表示零旋转。四元数前三个字母和位置坐标相同，代表的含义却完全不同，不能当成位置使用。

### 为什么先查原始字段，再规范模长

`imu_orientation.hpp` 把共有工作提出来。它收到只读 `imu` 和可写 `q`，从消息的四个字段构造暂存四元数。姿态协方差首元素 −1 是该消息约定的“姿态不可用”。模长为零时无法归一化；非有限值也不能继续算。代码提前返回 `false`，调用方因此跳过本次输入。通过检查后归一化，降低模长微小偏差对后续计算的影响。

| 接到的情况 | 检查结果 | 回调如何继续 |
| --- | --- | --- |
| `(0,0,0,1)` 且未声明姿态不可用 | 模长 1 | 得到有效旋转矩阵 |
| `(0,0,0,2)` 且其余有效 | 可归一化 | 归一化后也是零旋转 |
| `(0,0,0,0)` | 模长为零 | 返回，等下一条消息 |
| 任一分量是 NaN 或无穷 | 模长平方不有限 | 返回，保护下游 |
| 协方差首元素 −1 | 发布者声明无姿态 | 返回，避免使用无效的姿态字段 |

测试时常见的全零消息只有在填上有效姿态后才能驱动这里计算。还要核对上游四元数顺序，交换 `w` 与 `x` 可能产生完全合法却含义错误的旋转，普通数值检查无法识别。

### 代码为什么要乘一个“朝下”的向量

在传感器自己的参考系里，程序用 `(0, 0, -1)` 表示与缆绳方向对应的局部向量。四元数只描述旋转，乘这个向量才得到它在目标参考系的方向。船代码先用四元数构造 `tf2::Matrix3x3`，再做矩阵乘向量。起点是“缆绳在传感器自家坐标里指哪里”，终点是“以计算参考系看那一根箭头指哪里”。

单位方向的 Z 分量接近 −1，意味着缆绳接近竖直向下。`-cable.z()` 接近 1，反余弦得到很小的倾角。Z 分量是 −0.5 时，反余弦约为 60°。这条计算只查看竖直分量，因为 unit 向量模长是 1。反余弦输入由于浮点误差可能变成 1.0000000001，先限制到 `[-1, 1]`，使它处在函数定义域。

### 为什么用 atan2 和倾角门限

水平面上的箭头由 X、Y 两个分量决定。`atan2(y, x)` 同时使用两个分量，能区分象限。比如 `(x, y)=(1, 1)` 得 45°，`(-1, 1)` 得 135°。两个数如果直接相除，可能失去象限信息，还会遇到 X 为零。`atan2` 的结果通常用弧度表示。

缆绳竖直时，水平投影 `(x, y)` 几乎是 `(0, 0)`。从一个几乎没有长度的箭头计算方向，极小的噪声也会转出很大的角度。代码用滤波后的倾角与 0.035 弧度（约 2°）比较。达到分支时计算水平角，减同一帧 IMU 的偏航角以获得程序定义的相对角，再给方位角滤波器。接近竖直时走默认输出 0 的分支。这里的默认角含有算法“水平角不可靠”的选择，观察到 0 时可以结合倾角判断原因。

RPY 是 Roll、Pitch、Yaw（横滚、俯仰、偏航）。源码用 `getRPY` 从矩阵提取 RPY，这里需要的是 `yaw`。它来自**缆绳 IMU**。母船航向节点另有自己的输入，位置节点的源码可以用订阅列表区分两条链路。

### 为什么滤波器要记住上一帧和方差

`AngleFilter` 有两项状态，估计值和方差。每次更新先按固定步长预测不确定度，再用当前估计和测量的差更新状态。预测方差大时，增益更偏向接受新测量。测量噪声参数大时，增益减小，新测量只拉动旧估计一小部分。两个独立对象保证倾角历史不混进方位角历史。

假如估计是 +179°、新测量是 −179°。直接相减得到 −358°，会让估计沿很长的方向转。用 `atan2(sin(error), cos(error))` 把角差规约到主值区间，可得到约 +2° 的短角差。船用相同技巧规约更新后的估计。这里是单个角度上的有状态滤波，和最后将子船位置及姿态组合的 EKF 处在不同环节。

## 18 · 标定什么时候改变数据，母船航向为什么另算

### 把“原始角”的来路接到“用来算位置的角”

实际传感器安装有安装偏差，原始角往往与外部标尺量得的方位不同。实船标定得到一组参数。标定器接收 `/sensor/cable_azimuth_original`，完成转换再发 `/sensor/cable_azimuth`。输入输出都使用弧度。用一个节点封装这一步，定位节点只依赖最后的角度约定，上游不同型号的设备能各自建立对应标定。

处理分三步。第一步调整零偏并对选定范围增加一圈，以便落在拟合的区间。第二步用五次多项式把输入角映射到标定角。第三步用正余弦与 `atan2` 把结果规约回主值区间。你看到结果从接近 −π 换到 +π，应先判断是同一个物理方向的不同数值表示，还是实际数据跳变。

用简化系数 2、3、4 手算霍纳法，输入 x = 0.5：

| 迭代 | 做的运算 | 当前结果 | 展开式 |
| --- | --- | --- | --- |
| 开始 | 初始化 | 0 | 0 |
| 加最高次项系数 | `0 * x + 2` | 2 | 2 |
| 加一次项系数 | `2 * x + 3` | 4 | 2x + 3 |
| 加常数项系数 | `4 * x + 4` | 6 | 2x² + 3x + 4 |

换成六个系数时，第一次把最高次系数带入，后面五次乘算形成五次项。方式相同。船的常数项和零偏使“原始角 = 0”算出来的“标定角”约为 −0.024 弧度。若缆长 5 米、深度 3 米、从原始角开始喂入，Y 大约是 `4 * sin(-0.024) ≈ -0.096 m`。若直接给标定后话题喂 0，Y 为 0。两组断言对应两种测试入口。

### 相似的名字，使用场景不同

| 信号 | 读哪个文件看到 | 数值从哪来 | 单位 | 用在哪里 |
| --- | --- | --- | --- | --- |
| 缆绳原始方位 | `imu_test1.cpp` | 缆绳 IMU 旋转出方向，再做滤波 | 弧度 | 作为标定器输入 |
| 缆绳标定方位 | `cable_angle_calibrator.cpp` | 原始角经实船拟合关系修正 | 弧度 | 作为相对位置解算输入 |
| 母船航向 | `mother_usv_msg_node.cpp` | 另一条飞控姿态消息取偏航，加 180° 安装偏置，再规约 | 度 | 独立输出给下游监听 |
| 子船姿态 | `ekf.yaml` 的 `imu0` | 子船飞控桥接的数据 | 四元数和角速度 | 同相对位置一道参与可选融合 |

MAVLink 是 Micro Air Vehicle Link（微型飞行器通信协议）。MAVROS 把 MAVLink 和 ROS 通信接起来。母船航向来自 `/mother/mavros/imu/data`，可选融合的子船 IMU 来自 `/mavros/imu/data`。这两个话题仅差命名空间，方向和设备角色不同。连接新机时要检查真正发布者的设备接线和节点配置。

## 19 · 从三个测量推到 X、Y、Z

先画一个侧视。以母船为参考，水平量为 r、深度大小为 d、缆长为 L。直线缆绳是假设，能给出 `L² = r² + d²`。从等式两边减去 `d²`，取非负平方根得到 r。在水平方向上再做俯视。角度 θ 从船头向左为正，由三角函数得到 `x = r cos θ`、`y = r sin θ`。垂直方向采用向上为正，所以 `z = -|d|`。

```text
侧视                                    俯视

母船 ●─────────┐                         +Y 左
      \ L     │ d                        ↑
       \      │                      子船●
        \     │                         / r
         \    │                        / θ
          ● 子船                母船 ●────────→ +X 前
       水平投影 r
```

| L / d / θ | r | x, y, z 约为 | 能说明什么 |
| --- | --- | --- | --- |
| 5 / 3 / 0 | 4 | (4, 0, −3) | 前方四米、水下三米 |
| 5 / 3 / π/2 | 4 | (0, 4, −3) | 左方四米、水下三米 |
| 5 / 3 / −π/2 | 4 | (0, −4, −3) | 右方四米、水下三米 |
| 5 / −3 / 0 | 4 | (4, 0, −3) | 当前程序把深度绝对值作为下方距离 |
| 5 / 5 / π/2 | 0 | (0, 0, −5) | 水平分量为零，角度不影响位置 |
| 5 / 6 / 0 | 0 | (0, 0, −6) | 源码把负平方差钳零，数据在几何上已不一致 |
| 5 / 0 / π | 5 | (−5, 0, 0) | 同一高度、后方五米 |

三角函数在 ±π 等位置可能产生接近零的很小浮点余量。自动检查通常用容差。L 与 d 都进平方，因此负的 L 也能算出数，这只反映公式和当前有限值检查的行为。对实船，应判断负缆长是否可能、是否应丢弃或记录诊断。深度大于缆长时，钳零避免根号出错，输出也可能需要质量标记，不能仅因收到一条消息就认为模型假设满足。

## 20 · 坐标、时间、协方差和 EKF 各回答一个问题

### 坐标标签回答“从哪里看”

`(4, 0, -3)` 单独出现时，只是一组三元数。`header.frame_id = "mother/base_link"` 说清了这些数以母船机体为参考。TF 来自 transform（坐标变换），用已知的参考系位姿来表示同一个点在另一个坐标系中的位置。`tf2` 根据参考系链和时间查找变换。

举例说，如果母船坐标相对地图沿 X 平移十米，轴没有旋转，母船坐标中的 `(4, 0, -3)` 在地图中就是 `(14, 0, -3)`。再假设母船前向相对地图的 X 轴逆时针转 90°，在同一平移下，四米前向会变成地图 Y 方向，结果约是 `(10, 4, -3)`。单改 `frame_id` 不会做这项数学变换。

### 时间戳回答“这条结果代表什么时候”

定位输出用 `now()` 记下这次解算时刻。三个数值输入是 `Float64`，只带数值。若深度在 10 秒前读过，今天的缆长更新仍能得到带现在时刻的位姿。为了知道某路读数何时采样，上游可以提供带时间戳的消息；为了知道节点什么时候拿到，可以同时记录接收时间。两者各有用途。跨设备的采样时间比较还依赖时钟同步。

### 协方差回答“这条测量有多稳定”

位姿由三维位置和三维角度不确定性描述，矩阵 6×6，顺序可按 `x, y, z, roll, pitch, yaw` 阅读。按行展开以后，第 0、7、14 项是位置对角线。后面第 21、28、35 是姿态对角线。对角方差越大表示该方向的不确定性越大。位置方差用平方米，角度方差用弧度平方。第一格若写入 `0.1 m²`，对应标准差约为 0.316 米，直觉上比直接把 0.1 读成误差米数更贴近含义。

缆绳解算只给位置。单位四元数作为消息里的姿态占位，代码用大的姿态方差，滤波配置也只从这个输入选取 XYZ。观察器若画出单位四元数朝向，要知道它来自占位值；真实子船姿态另从 IMU 读取。

### EKF 怎样把各自擅长的信息合起来

EKF 是 Extended Kalman Filter（扩展卡尔曼滤波器）。可以先想成“用上一时刻估计预测现在，再用新测量校正”。重要的是选择输入哪些分量可信。YAML 配置中一个布尔列表按 15 项选取状态，顺序是：

```text
位置 x/y/z → 姿态 roll/pitch/yaw → 线速度 x/y/z
  → 角速度 x/y/z → 线加速度 x/y/z
```

| 输入配置 | 哪些项为真 | 程序希望从这一路得到 |
| --- | --- | --- |
| `pose0: /solver/pose` | 最前面的三项 | 缆绳估计的相对 XYZ |
| `imu0: /mavros/imu/data` | 姿态三项与角速度三项 | 子船朝向和旋转速度 |

`two_d_mode: false` 表示保留三维处理。`frequency: 30.0` 是配置中的目标输出频率。滤波器需要能查到 IMU 安装参考系与子船机体的关系。launch 提供静态 TF `rov/base_link → rov/imu_link`，教学配置用零平移、零旋转。实际 IMU 若摆向另一侧，必须按安装变换。默认 `with_ekf=false`，此时没有这条滤波输出。开启后才可追到 `/rov/odometry/filtered`。

完整观察顺序是：先看三路测量与 `/solver/pose`，确认数和坐标对；再看子船 IMU 与 TF；最后看融合输出。这样一个位置偏移出现时，能判断它在曲线标定阶段就出现，还是在坐标变换或融合阶段产生。
