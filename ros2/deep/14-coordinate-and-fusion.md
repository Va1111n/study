# 把坐标变换和滤波结果放到同一张图里

这一章进一步解释第 20 课。先学“同一个点为什么有两组数字”，再看 `ekf.yaml` 中哪些位姿、速度、角速度真的进入估计。以后看到位置正确而画面不对，能先查参考系；看到额外滤波输出，能说清它使用了哪份输入。

## 1. 每一组 XYZ 都需要一个原点和三个方向

假设你站在母船上，朝着船头看。正前方 4 米、左方 0 米、向下 3 米的位置，可写成母船机体坐标中的 `(4, 0, -3)`。码头上的地图则选了另一个原点和方向。如果母船刚好在地图的 `(10, 0, 0)`，朝向地图 X，子船在地图的 `(14, 0, -3)`。同一个真实点，数字变化了，表示它被放进另一套坐标。

当母船转 90°，船头改朝地图 Y，原来母船坐标里的前方 4 米现在落到地图 Y。假设母船在地图中的平移仍是 `(10, 0, 0)`，结果是 `(10, 4, -3)`。运算顺序是先把方向旋转到地图轴，再加母船的位置。一般写作：

```text
点在地图里的坐标 = 母船朝向(rotation) × 点在母船里的坐标 + 母船位移(translation)
```

`frame_id` 的工作是注明输入来自哪个坐标系。改写这个字符串相当于换标签，不能替代矩阵乘法或 TF 变换。标签错误也可能让可视化把一组原本正确的数画到别处。

### 平移对位置和方向的影响不同

一个点有具体位置，需要加平移。方向向量说的是某个指向，换参考系只要旋转。例如缆绳的“向下”是一个单位方向，母船整体移十米，这个方向仍往下。方向与点用相似的三元数表示，但各自运算不同。`imu_test1` 用旋转矩阵乘方向，对它不加平移；把子船位置换成地图坐标则需要两者。

## 2. 用简单 C++17 程序把两步分开

下面只做绕 Z 的二维转向与三维平移，帮助看清运算顺序。一般的三维姿态已经由 `tf2` 等库表达。此处函数名说明转换方向，避免混淆“谁相对于谁”。

```cpp
#include <cmath>
#include <iomanip>
#include <iostream>

struct Point3 {
    double x;
    double y;
    double z;
};

Point3 in_map(const Point3& in_mother, double mother_yaw_in_map_rad,
              const Point3& mother_origin_in_map) {
    const double cosine = std::cos(mother_yaw_in_map_rad);
    const double sine = std::sin(mother_yaw_in_map_rad);

    // 母船坐标里的 x 和 y，旋转后分别贡献到地图 x、y。
    const double rotated_x = cosine * in_mother.x - sine * in_mother.y;
    const double rotated_y = sine * in_mother.x + cosine * in_mother.y;

    return Point3{
        rotated_x + mother_origin_in_map.x,
        rotated_y + mother_origin_in_map.y,
        in_mother.z + mother_origin_in_map.z,
    };
}

int main() {
    const Point3 relative{4.0, 0.0, -3.0};
    const Point3 mother{10.0, 0.0, 0.0};
    const double half_pi = std::acos(-1.0) / 2.0;

    const Point3 mapped = in_map(relative, half_pi, mother);
    std::cout << std::fixed << std::setprecision(2)
              << mapped.x << ' ' << mapped.y << ' ' << mapped.z << '\n';
    return 0;
}
```

位置经旋转由大约 `(4, 0, -3)` 变成 `(0, 4, -3)`，再加 `(10, 0, 0)`，输出 `10.00 4.00 -3.00`。实际 TF 查询需要给出来源和目标，还要在所需时刻有可用变换。逆向转换要先减平移，再用逆旋转，不能简单交换两边名字。构建自己的函数时，把目标与来源写到函数名或参数说明中。

## 3. TF 树怎么读

TF 来自 transform（坐标变换）。ROS 2 项目用 `tf2` 管理参考系之间的动态或静态关系。板子固定在子船上时，机体坐标与 IMU 安装坐标的相对位置固定，可用静态变换。地图与正在移动的船体之间则会随时间变化。

```text
示意 1：本教学软件启动入口可以提供
rov/base_link ──固定安装关系──→ rov/imu_link

示意 2：需要表达母船在地图中的运动时，会另有
map ──随时刻变化的母船位姿──→ mother/base_link
```

第一条是当前可选 EKF 入口里的静态关系，第二条是帮助理解的示意，需要系统实际有对应发布端。一个带 `header.frame_id = mother/base_link` 的位置消息本身只标出数据参考系，代码仍要让需要用变换的程序查到相应关系。

“静态”指两个参考系之间相对关系不变。哪怕子船快速转弯，IMU 相对机体的安装角依然固定。在当前教学配置中，`rov/base_link` 到 `rov/imu_link` 默认零平移、零旋转，意味着两个坐标系轴与原点被视为对齐。实船部署时要根据安装核对这个假设。IMU 消息实际的 `frame_id` 若写着完全不同的名字，把 launch 中变换的子节点改成正确的名字后，还要按真实姿态和偏移计算变换。

### 常见变换故障如何区别

| 观测 | 问哪一个具体问题 | 可能下一步 |
| --- | --- | --- |
| “找不到坐标系” | 消息里参考系的字符串是什么 | 对照发布端、TF 配置和订阅端目标参考系 |
| 两个参考系存在但不连通 | 树里有没有一条连续路径 | 查中间变换由谁负责发布，避免两端各自独立 |
| 有变换但提示时刻不可用 | 该测量的时间对应的变换在缓存里吗 | 对照时间戳、仿真时钟、变换频率和设备时钟 |
| TF 查到了，显示方向仍错 | 变换的平移和旋转是否符合安装 | 对照物理前左上轴与已知摆放，做量化验证 |
| 只有子船姿态不对 | 子船 IMU 的 frame 和姿态轴如何标记 | 追子船 IMU 与静态安装变换，不先改缆长几何公式 |

观测工具选的固定坐标系也是一项配置。消息生产的坐标正确，但工具选了不连通的参考系，也会画不出来。要先看消息本身，再查可视化。

## 4. EKF 用配置决定每个输入做什么

EKF 是 Extended Kalman Filter（扩展卡尔曼滤波器）。可以先理解为循环两步，每次用过去估计预测，把新测量按状态与可信度纳入校正。具体滤波使用一个状态列表。项目 `ekf.yaml` 用 15 个布尔值表示从某消息拿哪几项：

| 列表位置，从 0 算 | 这三位的含义 | 缆绳位姿 | 子船 IMU |
| --- | --- | --- | --- |
| 0、1、2 | 位置 X、Y、Z | 使用 | 不选择 |
| 3、4、5 | 横滚、俯仰、偏航 | 不选择 | 使用 |
| 6、7、8 | 线速度 X、Y、Z | 不选择 | 不选择 |
| 9、10、11 | 角速度 X、Y、Z | 不选择 | 使用 |
| 12、13、14 | 线加速度 X、Y、Z | 不选择 | 不选择 |

定位消息带有占位四元数，也有姿态三个方差。掩码只用位置，滤波器不会把它的占位方向当成新测量。IMU 同时有线加速度字段，当前这 3 项都为假，因此不能仅从 YAML 里看见一个“去重力”选项就断言当前系统已经把线加速度融进估计。先以掩码和实际接线为准，再看其它参数。

`two_d_mode: false` 使它按三维处理。如果把系统约束为二维，需要明确 Z、横滚、俯仰等如何处置。对上下存在明显距离的缆绳定位，随意启用二维模式会改变业务预期。配置的 30 Hz 是目标输出频率及调度设置的一部分，不能由此推断每秒有 30 个新的深度测量。

### 用一个一维例子理解“信谁更多”

下面只说明更新权重的直觉。设预测位置 4.2 米、预测方差 0.25 平方米，新位置测量为 4.0 米、测量方差 0.04 平方米。简单的一维更新可以写：

```text
权重 = 预测方差 / (预测方差 + 测量方差)
     = 0.25 / 0.29 ≈ 0.862

估计新位置 = 预测位置 + 权重 × (测量 - 预测)
           ≈ 4.2 + 0.862 × (-0.2)
           ≈ 4.028 m
```

如果把测量方差提高到 1.0，权重变为 0.2，估计约 4.16 米，离预测更近。这说明协方差会影响测量和预测各占多少。工程实际 EKF 涉及多维状态、矩阵及坐标变换。例子用来读懂“方差为什么不只是显示用的数字”。改协方差之前要确定设备测量噪声、建模误差和目标效果。

### 怎么区分滤波器没启动、没收到、收到后不能用

1. 看启动入口是否启用了 `with_ekf`，对应进程和节点是否活着。
2. 查 `/solver/pose` 有没有持续输出，知道定位计算已拿到三路输入。
3. 查子船 `/mavros/imu/data` 是否有有效姿态、frame 与采样时间。
4. 查两路数据所属坐标是否能转到它需要的参考系，失配时看日志和 TF。
5. 确认输出话题已按 launch 从 `odometry/filtered` 重映射到 `/rov/odometry/filtered`。
6. 给一组明显的子船非零偏航，并观察滤波朝向是否跟随。只有一条位置输出不足以证明子船 IMU 确实被融合。

## 5. 把最终里程计的两个 frame 联系起来

里程计消息可同时给出 `header.frame_id` 和 `child_frame_id`。前者是位姿表达的参考系，后者给本体（子坐标系）标识。测试关注 `rov/base_link` 作为子船机体。节点地址是通信命名空间（如 `/rov/...`），坐标系名称是消息合同（如 `rov/base_link`）。两处文字可以长得像，作用不同。重映射里程计话题不自动改变 frame。

从输出的位置再次向前追，找到它对应的 `/solver/pose`、传入的子船 IMU、参考系和启动参数。只有时间与空间都对齐的输入才适合比较。若把母船航向以度直接塞进子船的四元数位置，格式或语义都不匹配。数据类型、参考系、单位和采样时刻要一起验证，才能把一个滤波结果解释清楚。
