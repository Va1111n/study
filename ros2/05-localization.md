# 沿着真实数据读无人船的定位

这页是简明回顾。扩写版会分别代入四元数、标定角度、三角形边长和坐标变换，讲清每个数从哪一步来。[定位数据逐步推导](deep/06-localization-step-by-step.md)

先对照 `orangpi_ros2/src/usv_localization/` 中的四个 C++ 节点，再看可选滤波器。下面的箭头表示话题消息的流向。

```text
缆绳 /imu → imu_test1 → 原始方位角 → cable_angle_calibrator → 标定后方位角 ┐
外部设备 → /sensor/cable_length                                   ├→ pose_node → /solver/pose
外部数据 → /sensor/relative_depth                                 ┘           └→ /solver/debug_point

母船 /mother/mavros/imu/data → mother_usv_msg_node → /mother_usv/imu/yaw

/solver/pose + 子船 /mavros/imu/data → 可选 EKF → /rov/odometry/filtered
```

## 第 17 课 · 缆绳惯性测量和四元数

IMU 是 Inertial Measurement Unit（惯性测量单元）。`sensor_msgs/msg/Imu` 可装姿态、角速度、线加速度以及相应的协方差。在缆绳方位计算这一路，代码取的是消息中的姿态 `orientation`。姿态用四元数表示，四个字段在 ROS 消息里按 `x, y, z, w` 访问。这个四元数组合用来表示一个三维旋转，`(0, 0, 0, 1)` 表示不旋转。绕 Z 轴转 90 度时，可以用 `(0, 0, √0.5, √0.5)` 表示。

先读共用的 `read_orientation`。它从消息中填入四元数，检查是否声明没有姿态数据（`orientation_covariance[0] == -1.0`），再检查模长平方是否有限且离零足够远。通过检查后归一化，让四元数的长度为 1，再交给 `tf2` 计算。这个函数也被母船航向节点使用。

然后在 `imu_test1.cpp` 找三个计算步骤。

1. **把传感器的“向下”换到参考系。** 代码把四元数变成旋转矩阵，用它乘局部向量 `(0, 0, -1)`。结果 `cable` 有三个分量。矩阵乘向量这个写法用到 C++ 的运算符重载，这里由 `tf2` 类型定义了乘法的含义。
2. **求倾斜程度。** `acos(-cable.z())` 表示缆绳与正下方的夹角。输入先钳到 `[-1, 1]`，避免浮点误差造成反余弦越界。代码把这个倾角送进 `tilt_filter_`。
3. **求水平投影指向。** 滤波后的倾角大于 0.035 弧度时，用 `atan2(cable.y(), cable.x())` 算水平角，再减去同一帧缆绳 IMU 的偏航角，送进 `azimuth_filter_`。靠近竖直时，水平分量太小，细微噪声就会引起方向大变化，程序走默认输出 0 弧度的分支。

RPY 是 Roll、Pitch、Yaw（横滚、俯仰、偏航）。本例用 `getRPY` 取得偏航。绕一圈回到同一方向，数值有可能从 +179° 跳到 −179°；实际相隔约 2°。滤波器对差值计算 `atan2(sin(error), cos(error))`，得到主值区间内的短角差。两个滤波对象各保存估计值与方差。每帧用固定的 0.01 秒步长预测方差，计算新测量的权重，再向测量更新。实际采样频率明显偏离当初调参所用的 100 Hz 时，可以检查固定步长是否仍合适。

## 第 18 课 · 缆绳方位标定和母船航向

### 缆绳标定

`cable_angle_calibrator.cpp` 订阅原始角，剔除非有限值，然后先减安装零偏，再把靠近负半圈的部分角度移到拟合时使用的角度区间。多项式系数按最高次项到常数项排列，代码每轮都做“当前结果乘输入，再加系数”。给定 `a, b, c` 时，三轮结果依次是 `a`、`ax + b`、`(ax + b)x + c`。这叫霍纳法，船上同样的结构处理五次多项式。最后再将输出角规约到约 `[-π, π]` 的主值区间。

这些系数来自原船标定。原始角 0 弧度走完标定后会得到一个小偏角，约 −0.024 弧度。第 19 课的 `(4, 0, −3)` 算例给的是**标定后** 0 弧度。看到测试里的 Y 有一个小偏移，可以先检查注入的是上游原始角还是标定输出。

### 母船航向

`mother_usv_msg_node.cpp` 从 `/mother/mavros/imu/data` 读取飞控姿态，取偏航，然后按原安装约定加 π，将结果规约到 `[0, 360)` 度。输入偏航 0° 时输出 180°，输入 90° 时输出 270°。这个数值经 `/mother_usv/imu/yaw` 定时发布。MAVROS 是连接 MAVLink（Micro Air Vehicle Link，微型飞行器通信协议）设备和 ROS 的桥接软件。飞控也常用于水面艇，名称里的“飞控”说明控制器的来源和功能类别。

定位节点订阅的是 `/sensor/cable_azimuth`，以弧度计。母船航向话题独立运行，以度计；从定位节点的三次 `subscribe_scalar` 调用就能验证两条数据路径。

## 第 19 课 · 从缆长、方位角和深度算三维位置

这个算法近似认为缆绳拉直。缆长是斜边，深度绝对值是竖直边，水平距离是另一条直角边。平面里以船头为 X 正向、左舷为 Y 正向。Z 向上，水下为负。

```text
水平距离 r = √max(0, 缆长² − 深度²)
x = r × cos(标定后方位角)
y = r × sin(标定后方位角)
z = −|相对深度|
```

缆长 5 米，标定后方位角 0 弧度，深度 3 米。水平距离是 4 米，余弦为 1，正弦为 0，因此位置是 `(4, 0, −3)` 米。缆长和深度相同，水平距离就是零。若方位角改为 π/2，水平距离仍为 4 米，X 接近零、Y 约为 4 米，表示从正前方转到左侧。

| 这一条消息到达时 | 缓存状态 | 输出行为 |
| --- | --- | --- |
| 缆长 5 米 | 只有缆长 | 返回，等待另两路 |
| 方位角 0 弧度 | 缆长和方位角都有 | 返回，等待深度 |
| 深度 3 米 | 三路都有 | 发出位置 |
| 新缆长 5.1 米 | 三路仍有，新旧数据混用 | 用新缆长和缓存的角度、深度重算 |

消息到达顺序可以不同。任一有效输入都会调用 `publish_position`，三路都齐才继续。若深度绝对值超过缆长，程序将负的平方差钳为零，仍输出相同的深度。这个分支保护平方根计算；几何上这组测量存在不一致，诊断时要同时看单位、读数时刻和物理量程。缆绳明显松弛或弯曲时，实物也可能偏离直线假设。

## 第 20 课 · 坐标系、时间戳、协方差与 EKF

`/solver/pose` 发送 `PoseWithCovarianceStamped`。Pose 是位姿，包括位置和姿态。Stamped 表示它还有一个包含时间和坐标系的头部。

| 字段 | 本工程填的内容 |
| --- | --- |
| `header.frame_id` | 坐标表达在哪个参考系，缺省为 `mother/base_link` |
| `header.stamp` | 此次解算时刻，来源是节点的 `now()` |
| `pose.pose.position` | 子船相对母船的三个笛卡尔坐标 |
| `pose.pose.orientation` | 单位四元数占位，缆绳只解算位置 |
| `pose.covariance` | 6×6 的位姿协方差按行展开，对角下标 0、7、14 对应 XYZ 位置方差 |

协方差描述测量的不确定性。位置方差单位为平方米，姿态方差单位为弧度平方。坐标系决定“同一组三元数指向哪里”，是消息含义的一部分。TF 来自 transform（坐标变换）。`tf2` 管理带时间的坐标系变换，可查询两个参考系如何换算。仅改 `frame_id` 只会改标签。要换个参考系表达同一点，需要正确的变换，并计算坐标。

默认 launch 只启四个计算节点。打开 `with_ekf` 后额外启动 `robot_localization` 和子船静态 TF。EKF 是 Extended Kalman Filter（扩展卡尔曼滤波器）。它先根据运动模型预测状态，再根据信息来源和不确定性修正估计。读 `ekf.yaml` 的配置掩码时，以每组三位看 15 项，顺序是位置、姿态、线速度、角速度、线加速度。缆绳位姿只取 XYZ，子船 IMU 取 RPY 和角速度。配置频率是 30 Hz，并把滤波输出重映射到 `/rov/odometry/filtered`。

教学配置给出了 `rov/base_link → rov/imu_link` 的零偏移、零旋转静态变换。实船要按安装方向、位置和 IMU 的实际 `frame_id` 核对。输入带时间戳时，也要检查两台机器的时钟和消息时间。位置节点的三个 `Float64` 输入没有采样时间，输出盖的是解算时刻。滤波器的 `sensor_timeout` 无法从不断更新的输出时间戳里识别某一路底层读数已经停更，适合回到解算端处理数据新鲜度。
